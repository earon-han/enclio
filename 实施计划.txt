**仓库一实施计划：bwrap＋网络代理＋seccomp**

仓库名：`enclio`。

目标：构建类似 Codex 沙箱路线的独立 Linux 沙箱项目，最终提供可安装、可调用、可验证的 CLI。参考项目的具体能力和实现，需要在调研阶段核实。

本仓库独立维护代码、文档、任务、测试、CI、版本和发布产物。设计阶段考虑通用 Agent 调用方式，不包含 Jiuwen 适配任务。

**一、任务清单**

| ID | 任务 | 主要交付物 | 完成标准 |
|---|---|---|---|
| A00 | 明确首版范围 | 目标用户、使用场景、目标平台、权限要求、首版能力与排除项 | 明确要解决的问题及可验收目标 |
| A01 | 初始化仓库和协作流程 | README、许可证、AGENTS、任务台账、Issue/PR 模板、基础检查 | 仓库可独立检出，开发与验证入口明确 |
| A02 | 调研参考实现与运行环境 | 固定版本的参考资料、来源与许可证清单、环境探测记录 | 区分可借鉴、可复用和需要自行实现的内容 |
| A03 | 完成方案设计与评审 | 威胁模型、总体设计、CLI 契约、兼容性说明、测试计划、设计决策记录 | bwrap、代理、seccomp 及执行管理职责明确，关键疑问有验证任务 |
| A04 | 验证关键机制 | 最小原型、能力探测工具、目标环境实测记录 | 核心路径可实施，平台限制与阻断条件明确 |
| A05 | 建立 CLI 和构建骨架 | 命令入口、帮助、版本、配置校验、日志、错误处理、构建脚本 | 用户能安装并运行最小示例，错误输入得到清晰反馈 |
| A06 | 实现沙箱执行能力 | 已评审的文件限制、系统调用限制、命令执行和输入输出功能 | 正向功能与拒绝行为均有测试证据 |

推进顺序：A00—A03 先完成；A04 与 A05 可以并行；接口确定后，A06 与 A07 可以并行；随后完成 A08—A11。

**二、设计阶段必须回答的问题**

A03 需要形成可评审文档，回答以下问题；当前计划不预先确定实现方式：

- 首版支持哪些 Linux 发行版、CPU 架构及容器环境？
- bwrap、网络代理和 seccomp 各自承担什么安全责任？
- 文件、网络、进程、IPC、环境变量和继承 FD 的限制范围是什么？
- 如何启动、取消、超时终止和清理后台后代？
- 缺少运行条件时如何报告，哪些情况拒绝启动？
- 开发语言、依赖、构建方式和发布包如何选择？
- 性能预算、清理完成条件和版本发布门槛是什么？

**三、Agent 调用要求**

面向通用 Agent，通过 CLI 完成调用。设计与验证至少覆盖：

| 调用环节 | 要求 |
|---|---|
| 启动 | 支持非交互执行，能传入命令、工作目录、策略和必要环境 |
| 输出 | 能明确区分业务 stdout、stderr 与沙箱自身日志 |
| 结果 | 提供机器可读结果，区分业务失败与沙箱启动或执行失败 |
| 控制 | 明确超时、取消、信号和后代清理的行为 |
| 兼容 | CLI 和结果格式具有明确版本约定 |

具体命令、字段、传输格式和流式事件形式，在 A03 中确定。提供一个不依赖专有 Agent 框架的调用示例。

**四、验证与发布要求**

A09 至少覆盖：

- 文件授权、只读保护、路径与符号链接绕过。
- 代理访问、删除代理配置、直接 socket 访问及其他网络绕过。
- 继承 FD、控制通道、权限和替代系统调用入口。
- 正常退出、非零退出、超时、取消、启动中途失败。
- 代理故障、调用方退出、后台进程及重复执行后的资源残留。
- 设计中声明支持的真实平台和架构。

每项安全负例都要确认测试程序实际执行。启动失败单独记录为 BLOCKED，不能当作安全拒绝通过。

性能报告包含源码版本、策略、环境、原始样本和失败数。预览版与稳定版分别设置发布条件。

**五、后续会话的进展与提交管理**

在仓库中维护实施计划、设计决策和进度台账。每个任务记录：

```text
任务 ID、状态、交付物、关联提交、
验证方式与结果、阻断原因、下一步
```

任务状态统一为：待办、进行中、受阻、完成。

每完成一个可独立审查的改动，运行相关检查，形成关联任务 ID 的提交并推送远端。提交记录、验证报告和发布产物应能追溯到同一源码版本。

设置三个检查点：

1. **设计可实施**：A03—A04 完成。
2. **CLI 功能完整**：A06—A08 完成。
3. **版本可发布**：A09—A11 完成。

后续会话从核对仓库和 A00 开始，持续跟踪设计、开发、验证、代码提交及发布进展。关键机制验证完成后，再细化工期。
